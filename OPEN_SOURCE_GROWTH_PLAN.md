## Positioning

Use one clear public identity:

> I build AI systems, browser productivity tools, and developer utilities in public.

This is broad enough for the current portfolio, but specific enough that visitors know why to follow.

## Repo Focus

### Flagship: snapwrite-ai

Why: It has a live Chrome Web Store listing, a simple value proposition, and a public audience beyond classmates or recruiters.

Next outcomes:

- README explains the problem in under 10 seconds.
- Setup takes under 5 minutes.
- Contribution path is obvious.
- Issues have `good first issue` and `help wanted` labels.
- Security/privacy docs exist because browser extensions process user-selected text.
- Social launch copy links directly to the install page and repo.

### Secondary: arena

Why: It demonstrates deeper AI engineering through LLM evals, prompt regression tests, optimization, and CI gates.

Next outcomes:

- Make standalone setup clearer.
- Add a minimal example that does not require private Respan context.
- Publish one technical write-up around "Jest for prompts".

## Weekly Operating Loop

Every week:

- Ship one visible improvement to `snapwrite-ai`.
- Open or close one contributor-friendly issue.
- Make one small PR to another open-source repo in the same space.
- Post one build note with a demo, screenshot, or changelog.
- Reply to every issue/comment quickly and concretely.

## Contribution Targets

Look for low-risk issues in:

- Chrome extension examples and Manifest V3 utilities.
- OpenAI/Anthropic SDK docs or examples.
- LLM eval and prompt testing repos.
- GitHub profile/dashboard tooling.
- Student productivity or education tools.

Preferred PR types:

- Broken docs or examples.
- Reproducible bug fixes.
- Test coverage for edge cases.
- Small UX improvements.
- CI or setup fixes.

## Quality Bar Before Promotion

Do not promote a repo heavily until it has:

- Clear README.
- License.
- Contribution guide.
- Issue templates.
- Security/privacy notes if it processes user data.
- At least one runnable test or documented manual verification path.
- A short list of well-scoped issues for contributors.

## Metrics To Review Weekly

- New followers.
- Stars by repo.
- Profile views, if available.
- Repo traffic/clones, from GitHub Insights.
- Issue/PR response time.
- External PRs opened, merged, or reviewed.
- Which launch channel produced real visitors or stars.
